# История изменений

Ниже фиксируются изменения, которые были подтверждены в проекте и отражают актуальное состояние реализации.

## v2.2.0 (последние 18 часов) — modular plugins, 4K resolution, streaming pipeline & notification tracking

- **Модульная архитектура источников видео (`SourcePluginRegistry`)**:
  - Реализован реестр плагинов источников `SourcePluginRegistry` (`AnimelibPlugin` и `KodikPlugin`).
  - Устранена жесткая зависимость от единого провайдера; добавлена автоматическая регистрация через `registerSourcePlugin`.
  - Удален устаревший монолитный сервис `animelibService` и блокирующие HTTP-пинги CDN в `BaseSourcePlugin`.
- **Поддержка ультравысоких разрешений 4K (2160p) и 2K (1440p)**:
  - Парсер плееров в `AnimelibPlugin` обновлен для считывания качеств `2160` и `1440` (как строкой, числом, так и по шаблонам `_2160.mp4` / `_1080.mp4`).
  - Добавлены бейджи качеств `4K 2160p`, `2K 1440p`, `1080p`, `720p`, `480p`, `360p` в интерфейс выбора потоков Telegram.
- **Динамическая сортировка озвучек с пользовательским приоритетом**:
  - Любимые студии озвучки пользователя автоматически поднимаются на верх списка со значком `⭐` как в карточке тайтла, так и при формировании кнопок скачивания серии.
- **Потоковый HLS/MP4 конвейер загрузки без CLI FFmpeg**:
  - Ликвидирован риск Out-Of-Memory при скачивании тяжелых серий за счет потоковой передачи `axios` + `stream.pipeline` / `createWriteStream`.
  - Загрузка HLS реализована через скачивание нативных TS-сегментов и их последовательную конкатенацию без внешнего бинарника FFmpeg, что предотвращает сбои на Windows и ошибки доступа к файловой системе.
- **Интерактивное управление колокольчиком (`toggle_bell`) в Telegram**:
  - В карточку тайтла добавлена инлайн-кнопка `[🔔 Отслеживается]` / `[🔕 Не отслеживать]` (`callback_data`: `toggle_bell:<mediaId>`).
  - Статус подписки мгновенно переключается в таблице `animelib_sync` (`dbService.toggleSubscription`) с подтверждением через `ctx.answerCallbackQuery()` и динамическим обновлением текста кнопки.
- **Глубокий разбор подписок AnimeLib и исправление «Запланированного»**:
  - Метод `fetchBookmarksPaginated` обновлен для извлечения флага уведомлений из всех возможных полей API AnimeLib (`has_notifications`, `subscription.status`, `subscription.notice`, `notify`, `notice`, `is_subscribed`, `user.subscribed`, `meta.has_notifications` и др.).
  - В разделе «Запланированное» исправлена фильтрация: при активном фильтре отображаются только тайтлы с колокольчиком (сверка по объекту и SQLite).
  - При отсутствии тайтлов выводится понятное сообщение с подсказкой о включении отслеживания кнопкой `[🔔 Отслеживать]`.
  - Исправлен сброс состояния фильтра при переключении страниц пагинации.
- **Стабильность сети и очистка доменов**:
  - Вычищены неработающие домены (`video.animelib.me`, `cache.lib.social`, `anmli.org`), вызывавшие ошибки `getaddrinfo ENOTFOUND`.
  - Официальный рабочий эндпоинт API AnimeLib закреплен на `https://hapi.hentaicdn.org/api` с заголовками `Site-Id: 5`, `Origin` и `Referer`.
- **Гостевой режим и мониторинг хранилища**:
  - При отсутствии, отзыве или истечении токена Shikimori бот прозрачно переходит в режим `AnimeLib ➔ SQLite`, информируя пользователя и не прерывая работу.
  - В меню настроек Telegram-бота добавлено отображение свободного места на диске и размера каталога `downloads/`.
- **Автономный протокол качества и документации (`GEMINI.md`)**:
  - В `GEMINI.md` зафиксированы правила обязательной автономной самопроверки (Static Type Check 0 ошибок, Telegram Limits < 64 байт, Streamed Data, Network Contracts) и обязательного обновления документации (`CHANGELOG.md` / `README.md`).

## v2.1.0 — comprehensive profile statistics, categories & background check reporting

- **Полная детализация профиля по категориям (`👤 Профиль`)**:
  - В карточку профиля Telegram-бота внедрена полная разбивка библиотеки по всем вкладкам:
    - 📺 **Смотрю сейчас** (онгоинги на активном отслеживании)
    - 📌 **В планах** (запланированные к просмотру тайтлы)
    - 🏁 **Просмотрено** (полностью просмотренные аниме)
    - ❤️ **Любимые** (избранное, код статуса `25`)
    - 🔁 **Пересматриваю** (код статуса `26`)
    - ⏸️ **Отложено** (код статуса `27`)
    - 🚫 **Брошено** (код статуса `23`)
    - ⚔️ **FATE** (специальная персональная коллекция франшизы Fate, код `2280926`)
  - 🚫 **Строгая фильтрация хентая**: тайтлы с кодом `2643707` полностью изолированы и исключены из всех подсчётов статистики библиотеки, рекомендаций и отчётов.
  - Добавлен расчёт общего объёма отслеживаемой библиотеки (`totalTracked`) без взрослых категорий.

- **Синхронизация и метрики Shikimori**:
  - Интегрирован модуль `src/services/libraryStats.ts` для агрегации данных из SQLite, локальных дампов и живого API Shikimori.
  - Отображение прогресса переноса: процент сматченных тайтлов (100%) и число перенесённых в Shikimori записей.

- **Журнал фоновых проверок серий (Check Reports & Scheduler)**:
  - Создана таблица `check_reports` и индекс `idx_check_reports_timestamp` в SQLite для хранения истории каждой проверки (количество проверенных тайтлов, свежих серий, статус и детали).
  - В карточку профиля добавлен блок **«⏱ Результат последней проверки»**:
    - Дата и время последней проверки с относительным временем («только что», «X мин назад»).
    - Количество проверенных онгоингов и сверка с Shikimori.
    - Статус проверки (найденные серии либо актуальность).
    - Обратный отсчёт до следующей автопроверки («через X мин»).
  - Планировщик фоновых проверок теперь мгновенно перезапускается (`restartScheduler`) при изменении пользователем интервала (15 / 30 / 60 мин) в настройках бота.

- **Web API и Dashboard интеграция**:
  - Добавлен REST эндпоинт `GET /api/library-stats` для отдачи агрегированной статистики категорий и последней проверки веб-клиенту.
  - Обновлены типы (`LibraryCategoryStats`, `CheckReportRecord`) и плашки статистики в веб-панели управления (добавлен блок «Любимые»).

## v2.0.2 — strict recommendations filtering & AnimeLib cache

- **Исключение просматриваемых и завершённых тайтлов из «Что глянуть?»**:
  - Добавлена кросс-проверка по Shikimori ID и нормализованным названиям (на русском и английском).
  - Тайтлы, которые пользователь уже смотрит (например, «Необъятный океан 3 / Grand Blue Season 3») или уже завершил, гарантированно исключаются из подбора.
  - Устранена путаница между категориями: выбор кнопки «[🔥 Онгоинг]» теперь строго подбирает свежие онгоинги сезона, а «[📌 Из «В планах»]» — строго неначатые тайтлы из списка ожидания.
- **Оптимизация и надёжность AnimeLib**:
  - Добавлен 45-секундный кеш запросов закладок для предотвращения спама и таймаутов на `hapi.hentaicdn.org`.
  - Лимит ожидания (timeout) увеличен с 15s до 25s.
  - Добавлен автоматический fallback на сохранённую локальную базу SQLite: при сетевых сбоях бот мгновенно использует локально кешированный список «Смотрю».

## Примечания

- `.env`, SQLite файлы и любые токены не должны попадать в Git.
- GitHub PAT должен иметь минимально необходимые права: только репозиторий и `Contents: Read and write`.
- Gemini `429` означает исчерпание квоты, а не локальную ошибку проекта.
