# История изменений

Ниже фиксируются изменения, которые были подтверждены в проекте и отражают актуальное состояние реализации.

## v2.0.2 — strict recommendations filtering & AnimeLib cache

- **Исключение просматриваемых и завершённых тайтлов из «Что глянуть?»**:
  - Добавлена кросс-проверка по Shikimori ID и нормализованным названиям (на русском и английском).
  - Тайтлы, которые пользователь уже смотрит (например, «Необъятный океан 3 / Grand Blue Season 3») или уже завершил, гарантированно исключаются из подбора.
  - Устранена путаница между категориями: выбор кнопки «[🔥 Онгоинг]» теперь строго подбирает свежие онгоинги сезона, а «[📌 Из «В планах»]» — строго неначатые тайтлы из списка ожидания.
- **Оптимизация и надёжность AnimeLib**:
  - Добавлен 45-секундный кеш запросов закладок для предотвращения спама и таймаутов на `hapi.hentaicdn.org`.
  - Лимит ожидания (timeout) увеличен с 15s до 25s.
  - Добавлен автоматический fallback на сохранённую локальную базу SQLite: при сетевых сбоях бот мгновенно использует локально кешированный список «Смотрю».

## v2.0.1 — launcher status handling

- Исправлена обработка кодов завершения команд в Windows launcher.
- Улучшены сообщения после остановки сервера и Telegram-бота.
- Добавлен актуальный production build для текущего релиза.

## v1.2.1 — polished launcher and bridge safety

- Добавлен обновлённый `start.bat` с ASCII-меню и безопасным flow:
  - `1` запускает preflight Shikimori и Telegram-bot
  - `2` запускает локальный Gemini -> GitHub bridge
  - `Q` закрывает интерфейс
- Добавлена валидация `.env` для Gemini/GitHub bridge.
- Добавлены проверки на ASCII-значения, запрещённые пути и секретные паттерны.
- Добавлено ручное подтверждение `y/N` перед внесением изменений в GitHub.
- Обновлены инструкции по использованию `pnpm ai:bridge` и безопасным PAT.

## v1.2.0 — OAuth, SQLite, bridge and launcher

- Исправлен `AnimeLib` bookmark retrieval для корректной работы через `hapi.hentaicdn.org`.
- Добавлена поддержка `Authorization: Bearer ...` и Cookie-based auth.
- Исправлены SQLite миграции и добавлена колонка `custom_note` для `animelib_sync`.
- Настроена OAuth2-авторизация Shikimori с сохранением токенов в SQLite.
- Добавлена логика refresh-token и синхронизация `user_rates`.
- Добавлен локальный Gemini -> GitHub bridge с функциями `commit_file` и `create_release`.
- Добавлена документация по безопасности и процедуре GitHub PAT.

## v1.1.1 — database repair and API stability

- Исправлен сбой, когда успешный ответ AnimeLib игнорировался из-за несовместимой схемы SQLite.
- Добавлена миграция и проверка таблицы `animelib_sync`.
- Изолированы ошибки синхронизации, чтобы они не ломали общий цикл обновлений.

## v1.1.0 — fresh Shikimori auth and token refresh

- Обновлены токены Shikimori после истечения `refresh_token`.
- Переключён канонический API host на `shikimori.io`.
- Проверена работа `user_rates` через OAuth2 и refresh flow.
- Подтверждён успешный запуск `pnpm test:shikimori`.

## v1.0.0 — initial tracker setup

- Инициализирован проект Anime Tracker Hub.
- Добавлена базовая работа с Telegram и AnimeLib.
- Добавлена локальная SQLite база для кэширования и статистики.
- Подготовлена структура для синхронизации с Shikimori.

## Примечания

- `.env`, SQLite файлы и любые токены не должны попадать в Git.
- GitHub PAT должен иметь минимально необходимые права: только репозиторий и `Contents: Read and write`.
- Gemini `429` означает исчерпание квоты, а не локальную ошибку проекта.
