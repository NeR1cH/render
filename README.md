# ANIME ASSISTANT v2.0 — окружение для Фазы 2

## 1. Разворачиваем n8n на VPS или Render

Предполагается чистый Linux VPS с установленным Docker и Docker Compose plugin
(`docker compose version` должен отвечать без ошибок), либо можно развернуть
сервис на Render.com через `render.yaml`.

```bash
mkdir -p ~/anime-assistant && cd ~/anime-assistant
# скопируйте сюда docker-compose.yml и .env.example

cp .env.example .env
openssl rand -hex 32   # вставьте результат в N8N_ENCRYPTION_KEY в .env
nano .env               # заполните остальные поля (пароль Postgres, домен, TZ)

# Важно: `env.example` — это только шаблон. Не используйте значения из него
# в реальном окружении. Создавайте `.env` и никогда не коммитьте его.

docker compose up -d
docker compose logs -f n8n   # проверяем, что стартовало без ошибок
```

По умолчанию n8n слушает только `127.0.0.1:5678` на самом VPS — наружу его
специально не открываем. Дальше два варианта:

- **Без публичного домена (проще для старта).** Заходите в n8n через
  SSH-туннель: `ssh -L 5678:localhost:5678 user@your-vps`, затем
  `http://localhost:5678` в браузере на своей машине. Для интеграции с
  Telegram используйте не Trigger-вебхук, а Telegram-ноду в режиме опроса —
  публичный HTTPS вообще не понадобится.
- **С публичным доменом и вебхуками Telegram.** Раскомментируйте сервис
  `caddy` в `docker-compose.yml`, направьте A-запись домена на IP VPS,
  добавьте рядом `Caddyfile`:

  ```
  n8n.example.com {
      reverse_proxy n8n:5678
  }
  ```

  `Caddyfile` — шаблонный конфиг, замените `n8n.example.com` на домен из
  `N8N_HOST` в `.env`.

  Caddy сам получит и обновит TLS-сертификат через Let's Encrypt.

## 2. Разворачивание на Render.com (альтернатива VPS)

Если вы предпочитаете облачный хостинг, можно задеплоить n8n и базу
Postgres на Render.com. Render автоматически выдаёт бесплатный SSL-сертификат,
но на бесплатном плане нужно учитывать:

- **База данных Postgres работает 30 дней** на бесплатном тарифе, затем
  требует пересоздания или перехода на платный план.
- **Веб-сервис n8n засыпает** через 15 минут бездействия. При первом
  обращении после «сна» ответ может занять 30–50 секунд.

### 2.1 Как использовать `render.yaml`

1. Создайте Git-репозиторий и добавьте в него файл `render.yaml`.
2. На Render.com выберите **New + → Blueprint**.
3. Подключите репозиторий с `render.yaml`.
4. Render автоматически создаст сервис `anime-assistant-n8n` и базу
   `anime-db`.
5. Нажмите **Apply** и дождитесь, пока сервис станет **Live**.

### 2.2 Что важно проверить после деплоя

1. Перейдите по URL, который выдаст Render, например:
   `https://anime-assistant-n8n.onrender.com`.
2. Зарегистрируйте аккаунт администратора n8n.
3. Если вы будете использовать Postgres напрямую внутри workflow через
   credential Postgres, возьмите данные из Render Dashboard:
   - Host / Internal Database URL
   - Port: `5432`
   - User / Password / Database: из страницы `anime-db`

## 3. Создаём Telegram-бота через @BotFather

1. Откройте Telegram, найдите **@BotFather** (это официальный аккаунт для
   регистрации ботов, у него синяя галочка верификации).
2. Отправьте команду `/newbot`.
3. Придумайте отображаемое имя бота (например, `Anime Assistant`) — это то,
   что увидят пользователи.
4. Придумайте username бота — он обязательно должен заканчиваться на `bot`
   (например, `anime_assistant_v2_bot`). BotFather проверит, что имя
   свободно.
5. BotFather пришлёт сообщение вида:

   ```
   Done! Congratulations on your new bot...
   Use this token to access the HTTP API:
   123456789:AAExampleTokenDoNotShareThisPublicly
   ```

   Это и есть **токен доступа** — храните его как пароль, не публикуйте
   и не коммитьте в git.
6. (Опционально, но полезно для личного ассистента) Отключите добавление
   бота в чужие группы и настройте команды:
   - `/setprivacy` → выберите бота → `Disable` — если хотите, чтобы бот
     видел все сообщения в групповых чатах (не нужно для личного
     использования один-на-один).
   - `/setcommands` → выберите бота → пришлите список команд, например:
     ```
     status - Текущий статус миграции/загрузок
     search - Найти тайтл на Shikimori
     ```
7. Напишите своему боту любое сообщение в личных сообщениях один раз —
   иначе Telegram не даст ему написать вам первым (ограничение платформы,
   не n8n).

## 3. Подключаем токен в n8n (Credentials)

1. В n8n: **Credentials → Add Credential → Telegram API**.
2. В поле **Access Token** вставьте токен, полученный от BotFather на шаге 2.5.
3. Сохраните — n8n сам проверит токен через `getMe` и покажет имя бота,
   если всё верно.
4. Дальше эту credential выбираете в любой Telegram-ноде (Trigger или
   обычной Telegram-ноде для отправки сообщений) в ваших workflow.

## 4. Что дальше (Фаза 2)

- Узел **Telegram Trigger** (или polling-нода) → парсинг команды/сообщения.
- Узел **HTTP Request** → GraphQL-запросы к Shikimori (тот же паттерн,
  что и в `migrate_animelib_to_shikimori.py` — компактный запрос, тот же
  User-Agent, тот же rate-limit).
- Узел **HTTP Request** → AniLiberty API v1 (поиск релизов/озвучек).
- Узел **HTTP Request** → qBittorrent Web API (обычно происходит по
  локальной сети/тому же Docker-хосту — если qBittorrent тоже в Docker,
  добавьте его в ту же сеть `anime_assistant_net`, чтобы обращаться к нему
  по имени контейнера, без публичного порта).
- Не забудьте настроить **регулярный бэкап** volume `n8n_data` (там лежат
  все workflow и credentials) и `postgres_data`.

## Важно про безопасность

- `.env` никогда не публикуйте и не коммитьте.
- `N8N_ENCRYPTION_KEY` — сохраните отдельно и не теряйте: без него n8n не
  расшифрует уже сохранённые токены/credentials после переустановки.
- Порт 5678 наружу не открывайте напрямую — либо SSH-туннель, либо
  reverse-proxy с TLS (см. раздел 1).
